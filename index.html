ServiceNow × Microsoft 365 Copilot
Which Connector Type for Which Activity

Three ServiceNow connectors across two fundamentally different connector types — understanding the distinction is critical for architecture and governance decisions.

📊 Copilot vs PP Connectors 🛒 Catalog Connector 🎫 Tickets Connector
Type 1
Copilot Connector
(Graph Connector)
⚙️ Configured in: M365 Admin Center → Search & Intelligence
Ingests and indexes non-Microsoft content into Microsoft Graph. Copilot and agents get answers from the index — not from ServiceNow directly. Best for high-frequency read operations at scale.
💡 Think of it as a search index — content is copied into Microsoft Graph once, then queried many times without hitting ServiceNow.
Type 2
Power Platform Connector
(Real-Time)
⚙️ Configured in: Copilot Studio → Agent Settings → Customize
Calls ServiceNow APIs live at runtime. No data movement or indexing. Each query hits ServiceNow directly. Best for real-time data, write operations, and transactional scenarios.
💡 Think of it as a live API bridge — every query goes to ServiceNow in real time. Great for write-back, not for high-frequency reads.
⚡
Key Architecture Decision — Per Microsoft Learn
Knowledge article search is a high-frequency read operation. Using a Power Platform connector for KB articles puts unnecessary stress on the ServiceNow backend — every employee query hits ServiceNow directly. The Copilot (Graph) connector is the right choice for KB articles because data is indexed into Microsoft Graph once and served from there. Use Power Platform connectors only for real-time data needs (catalog browsing, ticket status) or write operations (raise ticket, submit request).

Employee Scenarios — Which Connector Responds
📰 "How do I apply for leave?"
→ Graph Connector — KB article returned from Microsoft Graph index. No ServiceNow API call made.
📰 "How do I set up VPN?"
→ Graph Connector — Semantic search on indexed IT KB. Scales to all employees simultaneously.
🛒 "What can I request for my home office?"
→ PP Connector — Live catalog query to ServiceNow. HRSD scenario via Copilot Studio agent customization.
🛒 "Submit a laptop request for me"
→ PP Connector — Write operation to ServiceNow. Real-time is correct here — Graph connectors are read-only indexes.
🎫 "What's the status of my ticket?"
→ PP Connector — Live ticket lookup. ITSM scenario. Real-time needed for current status data.
🎫 "Raise an incident for my broken laptop"
→ PP Connector — Ticket creation (write). Real-time PP connector is the only correct option for write-back.

🚨
Don't Use PP Connector for KB Articles
KB article search is high-frequency. Using a Power Platform connector routes every employee query directly to ServiceNow's API — this can overload the SN backend. The Graph (Copilot) connector indexes content once and serves queries from Microsoft's infrastructure.
✅
PP Connector Is Right for Write Operations
Creating tickets, submitting catalog requests, updating records — these require real-time API calls. Graph connectors are read-only indexes. Power Platform connectors are the correct and only option for write-back scenarios.
⚠️
Knowledge Connector Still Preview for ESS
The ESS-specific Knowledge (Graph) connector integration is Preview only. Hierarchical permissions not supported — article-level ACL overrides KB-level. Attachments not indexed. Validate thoroughly before production rollout.
💡
Microsoft's Decision Rule
"If the goal is knowledge discovery and grounded Q&A at scale → use Copilot (Graph) connectors. If the goal is real-time knowledge or transactional steps → use Power Platform connectors." — Microsoft Learn
