ServiceNow × Microsoft 365 Copilot
Which Activity Goes Through Which Connector

Microsoft publishes three separate connectors for ServiceNow. Each connector handles a distinct content type with its own ACL model, crawl settings, and user experience. Based on official Microsoft Learn documentation.

📰 Knowledge Base Articles
Published IT & HR KB articles. Draft and retired articles excluded by default. Filtered via workflow_state=published.
✓ User Criteria ACL
🔐 Permissions Model
User Criteria evaluated at query time. Advanced flow required when scripted conditions or HR profile-based rules are in use. Must read user_criteria table.
⚠️ Advanced flow for ESS
🔄 Crawl Defaults
Full crawl: Daily. Incremental: Every 15 min. Permissions only updated on full crawl.
Preview · ESS Integration
🛒 Service Catalog Items
Active, published catalog items, bundles, and tasks. Default filter: active=true^workflow_state=published.
✓ User Criteria ACL
🔐 Permissions Model
Simple flow (no advanced scripts) or Advanced flow (scripted user criteria). Identity mapped via email to Azure AD UPN. Catalog role required on service account.
✓ Federated Auth Recommended
🔄 Crawl Defaults
Full crawl: Daily. Incremental: Every 15 min. Permissions only updated on full crawl. Not submitted requests — those become tickets.
GA · Read-Only Discovery
🎫 Ticket Records
Incidents (INC), Changes (CHG), Problems (PRB), Requests (REQ), Tasks (TASK). Scoped by assignment group and caller identity.
⚠️ High Sensitivity
🔐 Permissions Model
Based on assignment group membership and caller_id. Service account needs itil role. Apply crawl-time query filters to exclude HR, Legal, SecOps groups.
⚠️ Exclude sensitive groups
🔄 Crawl Defaults
Full crawl: Daily. Incremental: Every 15 min. NOT part of ESS Agent integration — separate connector for support team use cases.
GA · Support Teams
Employee Experience — What Gets Answered by Which Connector
📰 "How do I apply for leave?"
→ Knowledge connector surfaces HR KB article. Employee sees only articles their User Criteria permits.
📰 "How do I set up VPN?"
→ Knowledge connector returns IT procedure article. Semantic search — not keyword match.
🛒 "How do I request a new laptop?"
→ Catalog connector returns the laptop request catalog item — scoped to items that user's role can see.
🛒 "What software can I request?"
→ Catalog connector surfaces available software catalog items visible to the user's department/role.
🎫 "Show me open incidents for my team"
→ Tickets connector returns INC records scoped by assignment group. Support/IT use case.
🎫 "What's the status of change CHG001234?"
→ Tickets connector retrieves CHG record. User must have access per ServiceNow permissions.

🚨
Tickets Connector = Highest Governance Risk
Always apply crawl-time query filters to exclude sensitive assignment groups (HR, Legal, Security Ops). A misconfigured SN ACL means Copilot faithfully exposes that misconfiguration to users.
⚠️
Knowledge Connector Still Preview for ESS
The ESS-specific Knowledge integration is Preview only. Hierarchical permissions not supported — article-level ACL overrides KB-level. Attachments not indexed. Validate before production rollout.
✅
Catalog Connector — Federated Auth is Recommended
Per Microsoft docs, Federated Auth (OIDC via Entra ID) is the recommended auth path for the Catalog connector. No client secret storage or rotation needed. Assign catalog_admin + user_criteria_admin roles to the integration user.
💡
Three Connectors ≠ One ESS Integration
Knowledge connector is the only one Microsoft documents for ESS Agent integration. Catalog and Tickets are standalone connectors deployable independently in M365 Admin Center — surfacing content in Copilot search, not as part of the ESS agent flow.
